# Сервис «Дашборд»

## Общая информация

Необходимо разработать небольшой frontend-проект на **Angular** с использованием **Taiga UI**.

Проект должен представлять собой упрощённый сервис для управления каталогом товаров и просмотра истории покупок.

### Важно

В рамках тестового задания **не требуется разрабатывать backend**.

Все данные должны работать исключительно на стороне frontend:

- не использовать backend;
- не использовать реальные API;
- не использовать HTTP-запросы для получения или изменения данных;
- первоначальные данные должны быть определены в виде констант;
- при первом запуске приложения данные должны инициализироваться начальными значениями;
- все изменения данных должны сохраняться в `localStorage`;
- после обновления страницы добавленные и изменённые данные не должны пропадать.

# Задача №1. Инициализация проекта

## 1. Создание проекта

Необходимо создать новый проект на **Angular v22 или выше**.

Рекомендуется использовать:

- Standalone Components;
- SCSS;
- актуальные возможности Angular.

---

## 2. Установка Taiga UI

Необходимо установить и настроить **Taiga UI v5**.

Использовать необходимые для выполнения задания пакеты:

- `@taiga-ui/core`;
- `@taiga-ui/kit`;
- `@taiga-ui/cdk`.

Допускается установка дополнительных библиотек, если они действительно необходимы для реализации задания.

---

## 3. Маршрутизация

Необходимо реализовать следующие маршруты:

| Маршрут      | Страница        |
| ------------ | --------------- |
| `/login`     | Авторизация     |
| `/dashboard` | Каталог товаров |
| `/history`   | История покупок |

При открытии корневого маршрута `/` пользователь должен быть перенаправлен на соответствующую страницу.

---

## 4. Защита маршрутов

Маршруты:

- `/dashboard`
- `/history`

должны быть защищены с помощью `AuthGuard`.

Если пользователь не авторизован, необходимо перенаправить его на страницу авторизации.

# Задача №2. Разработка приложения

Рекомендуется использовать `Reactive Forms`.

# 3. Каталог товаров

Необходимо разработать страницу «Каталог товаров».

Страница должна содержать:

- кнопку добавления нового товара;
- таблицу со списком товаров;
- возможность редактирования товара;
- возможность удаления товара.

---

## 3.1 Добавление товара

По нажатию на кнопку «Добавить товар» должно открываться диалоговое окно.

В диалоговом окне пользователь должен иметь возможность указать:

- название товара;
- цену товара;
- НДС.

После успешного добавления:

- товар должен появиться в таблице;
- данные должны сохраниться в `localStorage`.

---

## 3.2 Редактирование товара

Для каждой записи должна быть доступна возможность редактирования.

По нажатию на кнопку редактирования:

- должно открываться диалоговое окно;
- поля должны быть заполнены текущими значениями товара;
- после сохранения изменения должны отображаться в таблице;
- изменения должны сохраняться в `localStorage`.

---

## 3.3 Удаление товара

Для каждой записи должна быть доступна возможность удаления.

Перед удалением необходимо:

- открыть диалог подтверждения;
- предоставить пользователю возможность подтвердить или отменить удаление.

После подтверждения:

- товар должен быть удалён из таблицы;
- изменения должны сохраниться в `localStorage`.

---

## 3.4 Таблица товаров

Необходимо реализовать таблицу со следующими колонками:

| ID  | Название | Цена | НДС | Действия |
| --- | -------- | ---- | --- | -------- |

Пример структуры товара:

```ts
interface Product {
  id: number;
  name: string;
  price: number;
  vat: number;
}
```

Где:

- `id` - уникальный идентификатор товара;
- `name` - название товара;
- `price` - цена товара без НДС;
- `vat` - размер НДС.

Колонка «Действия» должна содержать:

- кнопку редактирования;
- кнопку удаления.

---

# 4. История покупок

Необходимо разработать страницу «История покупок».

На странице должна отображаться таблица с несколькими тестовыми записями.

Каждая запись должна содержать:

| Поле             | Описание                       |
| ---------------- | ------------------------------ |
| ID               | Идентификатор записи           |
| Название товара  | Название приобретённого товара |
| Логин покупателя | Логин пользователя             |
| Сумма покупки    | Цена товара + НДС              |
| Дата операции    | Дата совершения покупки        |

Пример структуры:

```ts
interface Purchase {
  id: number;
  productName: string;
  username: string;
  amount: number;
  date: string;
}
```

Тестовые данные должны быть заданы в виде первоначальных констант.

# Работа с данными

Все данные приложения должны храниться локально.

Необходимо реализовать работу с `localStorage`.

Рекомендуется создать отдельный сервис для работы с данными.

Например:

- `AuthService`;
- `ProductsService`;
- `StorageService`.

### Требования

При первом запуске приложения:

1. Проверить наличие данных в `localStorage`.
2. Если данные отсутствуют - записать первоначальные тестовые данные.
3. Первоначальные данные должны быть определены в виде констант.

После этого:

- добавление товара должно сохраняться;
- редактирование товара должно сохраняться;
- удаление товара должно сохраняться;
- данные должны сохраняться после перезагрузки страницы.
